# Dev-Tools & Workflow Improvements from AI PR Review Audit

During a comprehensive audit of all open PRs, several issues and friction points were encountered while using the `dev-tools` CLI and following workflow instructions. To improve future agent workflows, these issues should be addressed.

## Issues Encountered & Remediation

1. **`setup-agent.sh` Timeout & Environment Instability**
   - *Issue*: Running `./setup-agent.sh` directly timed out after 400+ seconds. Also, initial attempts to use `td doctor` failed because the `td` command was not properly exposed in the `$PATH` after `setup-agent.sh` timed out.
   - *Workaround*: I had to bypass full setup, manually run `python3 -m pip install -e boomtick-pkg/cli/` to get `td` and `td-cli`, and run `source ~/.nvm/nvm.sh && nvm install 24 && nvm use 24` + `CI=true pnpm install --frozen-lockfile` manually to resolve unsupported Node/pnpm environments.
   - *Recommendation*: Improve `setup-agent.sh` logging/speed or ensure the container environment pre-installs these dependencies reliably so the agent doesn't waste time/tokens on cold starts.

2. **`td gh audit-pr <PR> --audit` TypeError**
   - *Issue*: Running the headless anti-pattern audit (`td gh audit-pr <PR> --audit`) consistently threw a `TypeError: string indices must be integers, not 'str'` originating from the CLI payload parsing logic.
   - *Workaround*: I had to manually fetch the context using `--fetch` (or `td agent plan-review --pr <PR>`), read the generated context markdown, author the review markdown manually, and post it using `--submit --execute --event COMMENT`.
   - *Recommendation*: Fix the underlying TypeError in `boomtick-pkg/cli/dev_tools/ai_service.py` or `boomtick-pkg/cli/dev_tools/cli.py` during the headless audit pipeline. The payload format it expects appears misaligned with what it generates.

3. **Inline Comment Line Resolution Failures**
   - *Issue*: When running `--submit --execute --event COMMENT`, the CLI frequently warned: `Warning: Failed to post inline comments due to line resolution error. Retrying with body comments...` (observed on PRs 3285 and 3282).
   - *Workaround*: The CLI successfully fell back to body comments, but this degrades the review experience.
   - *Recommendation*: Improve the GitHub API diff hunk parsing in `GitHubClient.post_pr_review` to reliably match source file line numbers to diff coordinates, particularly for Python and YAML files or files with large multi-line string changes.

4. **Undocumented JSON Metadata Requirements**
   - *Issue*: The AI review JSON payload schema defined in the `workflow-plan-pr-<PR>.md` guide and memory (which mandates `body` and `comments` arrays) was rejected by `--submit` with: `CLIError: Could not find a valid JSON metadata block (expected keys: comments, recommendation, labels)`.
   - *Workaround*: I manually updated the JSON payload in the markdown file to include the `"recommendation": "Approved"` key to bypass the parser constraint.
   - *Recommendation*: The `pr-review-skeleton` generated by `td agent plan-review` must be updated to correctly stub out the exact JSON schema required by `dev_tools/services/github.py`, explicitly including the `"recommendation"` key.

5. **`plan-review` vs `audit-pr` Instruction Overlap**
   - *Issue*: The prompt instructed using `td agent plan-review` which fetches everything, but then requested running `td gh audit-pr <PR> --fetch` and `--audit` again.
   - *Recommendation*: Clarify workflow documentation. If `plan-review` generates the `pr-context-<PR>.md` and `pr-review-<PR>.md` files, agents should be explicitly told to skip `--fetch` and just update the markdown skeleton.
